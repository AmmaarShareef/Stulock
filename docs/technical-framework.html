01
Shape

Product shape

StuLock ships as a browser extension first. Not a desktop app, not a phone app. This is the surface that carries the most features for the least build cost, and it is the only one where the enforcement signal you settled on — document.hidden as the violation trigger — is native rather than simulated.

v1 surface
Chrome + Edge MV3 extensionOne codebase, both stores. No installer, no code signing, no antivirus false positives, no per-OS build matrix.
v1.1 surface
Phone as sensor client (PWA)Top-down desk camera and paper capture over WebRTC. No app store, no Family Controls entitlement, no AccessibilityService.
v1.2 surface
Firefox buildSame WXT codebase, different target. Loses Gemini Nano — falls through to the server judge.
Web app role
Marketing, auth, dashboard, phone pairingNot a monitoring surface. A page cannot see sibling tabs; only an extension can.
Native desktop
Not builtRevisit only if native-app visibility becomes the top-requested feature. Tauri + a native-messaging host is the path, and nothing in this spec blocks it.

What v1 actually contains

Session contract, calibration wizard, four lockdown tiers (Locked In / Average / Light / Monitor Only), the vision core, phone-jail, present-but-idle detection, tab blocking with the relevance judge, the stuck-to-hint ladder, the intervention ladder, contest-a-flag, the session report, and scoring. The verified leaderboard ships the release after scoring is validated against the eval harness.

That is what makes them unit-testable without a browser, and it is what lets the same fusion logic run in the eval harness, the extension, and later a desktop wrapper.

03
Extension

Extension architecture

MV3 splits your code across five isolated contexts with different lifetimes and capabilities. Getting this partition right up front is the single highest-leverage architectural decision in the project, because moving work between contexts later is a rewrite, not a refactor.

ContextLifetimeOwns
Background service workerKilled after ~30s idleThe XState session machine. All chrome.tabs / windows / idle listeners. declarativeNetRequest rule management. The single source of truth.
Offscreen documentLives while the session runsThe camera stream, the vision worker, and Web Audio for the intervention ladder. Declared with reasons: ["USER_MEDIA", "AUDIO_PLAYBACK"].
Vision workerChild of offscreenAll inference. MediaPipe + ONNX Runtime on an OffscreenCanvas. Never touches the DOM.
Side panelUser-toggledLive session HUD — timer, current state, score, amnesty button. Visible without stealing a tab.
Content scriptPer blocked pageThe block interstitial, the friction unlock, and the justification box.

An extension is not just a popup. MV3 ships real HTML pages from chrome-extension://<id>/, and a page there is a full React SPA with routing and the whole viewport — indistinguishable from a hosted web app except for the URL. The dashboard, reports and calibration wizard all live there. It also gains something a hosted app cannot have: being same-origin with the extension, it reads IndexedDB directly, so reports render from local telemetry with no API layer and no network call.

Framework
WXTVite-based. Handles MV3 manifest generation, cross-browser targets, and HMR across contexts — the three things that make raw extension development miserable.
UI
React 19 + Tailwind v4 + shadcn/uishadcn vendors component source into your repo rather than a dependency, which sidesteps store review questions about bundled third-party code.
UI state
ZustandPer-context view state only. Never session truth — that lives in the service worker.
Cross-context messaging
@webext-core/messagingTyped request/response over chrome.runtime. Untyped postMessage across five contexts is where this class of project goes to die.
Charts
uPlot + one hand-written canvas rendererThe state strip is 5,400 segments for a 90-minute session. That is a canvas problem, not an SVG one. uPlot covers the ordinary time series at ~45KB.
Service worker death
Persist the machine snapshot on every transitionWrite actor.getPersistedSnapshot() to chrome.storage.session. Rehydrate on wake. Chrome will kill the worker mid-session and this is the only defence.
Camera ownership
One owner at a time, explicit handoffThe calibration page owns getUserMedia directly while calibrating — it needs a large live preview with the landmark mesh, and nothing else is running. The offscreen document takes ownership when a session starts.
Session preview
Opt-in mirror at 5 Hz, off by defaultOffscreen renders the annotated view to an OffscreenCanvas and posts a downscaled ImageBitmap only while a preview is open. A constant self-view is itself a distraction — show it at session start to confirm framing and face lock, then collapse to a status dot.
Keep-alive
Don't fight it — chrome.alarms at 25sPlus the offscreen document's open message port, which holds the worker alive while a session runs.
04
Vision

The vision pipeline

Four models, one worker, staggered cadences inside a fixed frame budget. Every model file is bundled in the extension package — never fetched from a CDN. The extension CSP forbids remote script, store review punishes remote code, and a student on campus wifi should not need a network round trip to start studying.

SignalModelRuntimeRateFeeds
Face, head pose, eyesMediaPipe FaceLandmarker@mediapipe/tasks-vision, GPU delegate15 HzPresence, PERCLOS, blink rate, yawn, head pose, gaze features
HandsMediaPipe HandLandmarkerSame10 HzWriting bouts, phone-in-hand, hand-in-notebook-region
ObjectsYOLO11n, COCO, ONNXonnxruntime-web, WebGPU EP2 HzPhone-jail occupancy (cell phone), notebook presence (book)
IdentityMobileFaceNet, ONNXonnxruntime-web, WebGPU EP0.2 HzEnrolled-face lock — ignore anyone who is not you

No OpenCV. opencv.js is an ~8MB WASM payload for classical operations this pipeline never performs. Phone-jail occupancy is a bounding-box intersection; writing detection reads wrist keypoints rather than pixels; a covered camera is mean luminance on a downscaled frame; notebook occupancy is point-in-rect. MediaPipe and ONNX supply the tensors and landmarks, and the remainder is arithmetic. Reaching for OpenCV here is a signal that something upstream has gone wrong.

Gaze — no fifth model

A dedicated gaze network is the obvious choice and it is the wrong one. You do not need gaze coordinates; you need to know which region of which screen someone is looking at, at roughly quadrant granularity, for your face on your monitor. That is a calibration problem, not a model problem.

  • Features — head pose yaw/pitch/roll from the facial transformation matrix, the eight eyeLook{In,Out,Up,Down}{Left,Right} blendshapes, and two iris-offset ratios from the landmark mesh. Fourteen numbers.
  • Calibration — nine-point, one dot at a time, about 40 seconds. Collect ~30 frames per point.
  • Model — ridge regression from those 14 features to normalised screen (x, y). Closed-form normal equations, about 30 lines, no dependency, fits in under 50ms.
  • Recalibration — triggered when residual error on a known-good state drifts, or when the user moves. Two points, ten seconds.

This handles the tiled-window bypass (a snapped video window beside the textbook) and the second-monitor case with one mechanism, and it degrades to head-pose-only if the eyes are occluded by glasses glare.

Frame plumbing

getUserMedia (offscreen)
  → MediaStreamTrackProcessor → ReadableStream<VideoFrame>
  → transfer to Worker (zero-copy)
  → OffscreenCanvas → per-model tensor
  → derived features only
  → throttled to 4 Hz → offscreen → service worker

Frames never leave the worker. Landmarks never leave the offscreen document. Only scalar features cross into the service worker, and only aggregates ever reach the network. That containment is both the privacy guarantee and the performance strategy.

Capture constraints: 640×480 at 15fps, facingMode: "user". Higher resolution buys nothing — MediaPipe downsamples internally, and 720p triples your per-frame copy cost for identical landmark accuracy.

Fusion

State machine and fusion

Engine
XState v5Three interacting hierarchical machines with timed transitions. Hand-rolled booleans become unmaintainable at about week three. XState also renders a diagram, which is the single best artifact you can put in the README.
Machines
sessionMachine (parent), attentionMachine, interventionMachineSession owns contract and lifecycle. Attention owns the fused state. Intervention owns the escalation ladder and is the only thing allowed to make noise.
Attention states
focused · writing · drifting · idle · away · violatingSix states, mutually exclusive, one per second in the log. This enum is your data model, your report, and your eval ground truth. Do not add a seventh without re-labelling the corpus.
Hysteresis
Asymmetric after delaysEntering violating takes 3s of sustained evidence. Leaving it takes 2s of compliance. Different thresholds in each direction is what stops buzzer chatter at the boundary.
Agreement rule
Two independent signals, alwaysNo intervention fires on a single detector. Gaze plus object, or gaze plus input-idle. This is the rule that keeps you out of Proctorio's failure mode.
Smoothing
5-second ring buffer + EMA per signalHand-written in packages/core, roughly 40 lines, fully unit-tested. No dependency.

06
Policy

Policy engine and the relevance judge

Blocking mechanism

chrome.declarativeNetRequest.updateSessionRules(), redirecting to an extension page carrying the URL and reason. Session rules clear themselves when the browser closes, which means a crashed session cannot leave a user permanently locked out of the internet — a failure mode worth designing away rather than apologising for.

Three-tier verdict

  1. Local rules — free, instantThe contract's own allowlist and blocklist, plus a shipped table of ~500 obvious domains. Resolves the large majority of navigations with no inference at all.
  2. Chrome Prompt API / Gemini Nano — free, on-device, ~200msLanguageModel.create() with the task description as context. Nothing leaves the machine. Availability is checked once at session start, not per navigation.
  3. Server judge — Supabase Edge Function → Anthropic APIFor Edge, Firefox, and any machine where Nano is unavailable or still downloading. Never blocks the navigation: the tab loads, the verdict arrives asynchronously, and a block applies on arrival.

Caching

Key on sha256(sessionTaskId + eTLD+1) in IndexedDB. One verdict per domain per task, reused for the whole session. A student visiting forty Stack Overflow pages costs exactly one judgement.

The server judge

Deno edge function, official TypeScript SDK. The task rubric is a stable prefix and gets a cache breakpoint; the URL and title are the only varying content.

// supabase/functions/judge-relevance/index.ts
import Anthropic from "npm:@anthropic-ai/sdk";
import { z } from "npm:zod";
import { zodOutputFormat } from "npm:@anthropic-ai/sdk/helpers/zod";

const Verdict = z.object({
  verdict: z.enum(["allow", "warn", "block"]),
  reason: z.string(),
});

const client = new Anthropic();

const response = await client.messages.parse({
  model: "claude-opus-5",
  max_tokens: 256,
  system: [
    { type: "text", text: RUBRIC, cache_control: { type: "ephemeral" } },
  ],
  messages: [
    { role: "user", content: `Task: ${task}\nURL: ${url}\nTitle: ${title}` },
  ],
  output_config: {
    effort: "low",
    format: zodOutputFormat(Verdict),
  },
});

return response.parsed_output; // null if parsing failed — guard it

Model choice is yours to make, not mine. The spec defaults to claude-opus-5 at $5 / $25 per million tokens. This call is roughly 400 input and 40 output tokens, so a heavy user generating 30 uncached verdicts a day costs well under a cent. If you later want that cheaper, claude-haiku-4-5 is $1 / $5 with a 200K context and is a reasonable fit for a two-line classification — but that is a deliberate cost-for-quality trade, so make it on purpose rather than by default. Set effort: "low" either way; a relevance verdict does not need deep reasoning.

Friction, not walls

A block verdict renders the interstitial with three exits: return to task (free), 20-second press-and-hold override (logged, small penalty), or type a one-line justification (logged, shown back in the report). A warn renders a dismissible banner. Every override is a training label for that user's future verdicts.

Biometric key handling

Generate a non-extractable AES-GCM CryptoKey at enrolment with crypto.subtle.generateKey(..., false, ...). CryptoKeys are structured-cloneable, so store the key object itself in IndexedDB — the raw key material is never exposed to JavaScript, not even yours.

Deleting that key destroys the template irrecoverably. That single operation is your published destruction schedule, which is a far stronger compliance position than a promise to delete rows on a server.

What is permitted to reach the network

An explicit allowlist, enforced by a single serialiser in packages/core that everything must route through. Nothing syncs unless it is on this list.

  • Session id, start and end timestamps, lockdown tier, declared task text
  • Per-state total durations — six integers
  • Flag count by severity, mean recovery time, final score
  • Subject label, self-reported question count, estimated versus actual duration

Never synced, under any setting: video frames, landmarks, embeddings, gaze coordinates, per-second state rows, URLs, page titles, or justification text. The URL and title reach the judge function transiently and are never persisted server-side.

10
Eval

The evaluation harness

This is the part that separates a demo from a product, and it is also the single most interview-legible thing you will build. It exists because you cannot ship an intervention whose false-alarm rate you cannot state out loud.

How it works

Playwright launches Chromium with the unpacked extension and a fake webcam fed from a file:

--load-extension=./apps/extension/.output/chrome-mv3
--use-fake-device-for-media-stream
--use-file-for-fake-video-capture=./packages/eval/clips/c07.y4m
--use-fake-ui-for-media-stream

Each clip has a sibling c07.labels.json giving ground-truth state per second. The harness runs the session, captures the emitted state stream, diffs it against the labels, and writes a metrics report. It runs in CI and it gates merges.

Metrics that gate a release

MetricGateWhy this number
False alarms per hour< 1.0Above this, users quit in the first session. This is the product-defining metric.
Per-state precision> 0.90Weighted toward violating, where errors are felt.
Notebook-vs-phone recall> 0.95The hardest confusion, and the one that destroys trust fastest.
State latency< 1.5s p95Slower than this and the buzzer feels arbitrary rather than causal.

The corpus — 20 clips, 3 to 5 minutes each

Record these deliberately. They are the specification of correct behaviour, and every one of them is a scenario where a naive implementation fails.

  • Reading a notebook for two minutes straight must not fire
  • Eyes closed, thinking, thirty seconds must not fire
  • Someone walks through frame behind you must not fire
  • Phone face-down in jail, untouched must not fire
  • Strong backlight, window behind you must not fire
  • Glasses with heavy glare must not fire
  • Drinking, stretching, adjusting posture must not fire
  • Phone lifted from jail and used must fire
  • Sustained gaze at a snapped window off-centre must fire
  • Present but idle — eyes on page, zero input, four minutes must classify as idle
  • Leaving the desk entirely must classify as away
  • Camera physically covered must classify as away

Record each in two lighting conditions and with at least two people. A detector validated on one face in one room is not validated — that is precisely the mistake the proctoring industry made and never recovered from.

Degradation ladder

Pre-decided, so the app never simply fails. On a machine without WebGPU, drop ONNX to the WASM SIMD backend and halve the object-detection rate to 1 Hz. If frame processing still exceeds budget, drop FaceLandmarker to 10 Hz, then disable HandLandmarker and mark writing-detection unavailable in the report. If even that fails, offer Monitor Only. The user is told which tier they are on, in plain language, in the side panel.

13
Learn

What to learn, in order

Ordered so that each step produces something runnable and nothing is learned before it is needed. Do not read ahead — the later items make far more sense once the earlier ones exist on your disk.

  1. MV3 extension fundamentalsManifest, service worker lifecycle, the five contexts, message passing. Build a throwaway extension that logs tab switches before you touch StuLock. The worker's death-and-rehydration behaviour is the concept everything else depends on.
  2. WXT + React + TailwindPort that throwaway into WXT. Get the popup, side panel and options page rendering. Now you have a shell.
  3. chrome.tabs / windows / idle / declarativeNetRequestThis is your entire enforcement layer. Build tier detection — distinguishing a tab switch from leaving the browser — and prove it before any camera code exists.
  4. MediaPipe Tasks VisionFaceLandmarker in a plain web page first, with landmarks drawn on a canvas. Understand blendshapes and the transformation matrix before moving into a worker.
  5. Offscreen documents + Web Workers + OffscreenCanvasMove the working pipeline into the extension. This is the hardest plumbing in the project and it is worth doing slowly.
  6. Linear regression, by handNormal equations and ridge regularisation. An afternoon of maths that replaces an entire gaze model and gives you something real to explain in an interview.
  7. XState v5Actors, guards, after transitions, persisted snapshots. Model the attention machine on paper first; the diagram is the design.
  8. onnxruntime-web + WebGPUExport YOLO11n, get it running in the worker, measure it. Learn the execution-provider fallback chain here rather than in production.
  9. Dexie + IndexedDBSchema, migrations, bulk writes. You will be writing one row per second, so bulk-write patterns matter immediately.
  10. Playwright with extensions and fake mediaBuild the eval harness the moment the first detector works. Every later change is safe because this exists, and it is the thing that makes the project credible.
  11. Supabase — Postgres, RLS, Edge FunctionsRLS is the concept to actually understand; it is what makes a public leaderboard over private data safe.
  12. WebRTC + WebCryptoLast, because both are self-contained. Offer/answer/ICE for the phone camera; AES-GCM and non-extractable keys for the face template.

What makes this legible on a resume: not the feature list — the eval harness. "Built a real-time multi-signal CV pipeline and validated it against a hand-labelled 20-clip corpus at under one false alarm per hour" is a sentence almost no portfolio project can honestly write. Lead with the number, not the idea.
